`RabbitMQManagementAPIError` extends `AmqpBaseError` (and so `BaseError`) with the code `RABBITMQ_MANAGEMENT_API_ERROR`. Breaking: the HTTP status of the RabbitMQ management API response moves from `statusCode` to `responseStatus`, and `statusText` becomes `responseStatusText`; the error also carries the `requestUrl`, and `toJSON()` returns all three. `statusCode` is now the status a service returns to its own client and stays 500. `error.name` becomes `'RabbitMQManagementAPIError'` instead of `'Error'`, and `toString()` returns `'[RABBITMQ_MANAGEMENT_API_ERROR] <message>'` instead of `'Error: <message>'`. A Fastify service that lets the error reach `fastifyErrorHandler` now answers with a 500 whose body is the error's `toJSON()` instead of the generic `InternalServerError`; #400 changes that handler so the body of a 5xx error hides its context, `requestUrl` included. Consumers read `error.responseStatus` and `error.responseStatusText` instead of `error.statusCode` and `error.statusText`, pass `{ requestUrl, responseStatus, responseStatusText }` to the constructor instead of `{ statusCode, statusText }`, and update any check on `error.name` or `error.toString()`.
